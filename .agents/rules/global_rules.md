# Правила роботи для ШІ-асистентів (Antigravity)

Цей файл містить глобальні правила для всіх агентів та суб-агентів. Всі агенти зобов'язані дотримуватися цих правил у всіх проектах без винятків.

## 1. Zero Hallucination Policy (Нульова толерантність до галюцинацій)
- **Заборонено додумувати логіку, код або бізнес-правила.** 
- Якщо інформації, контексту або коду недостатньо для впевненого рішення, агент зобов'язаний негайно зупинитись.
- Агент повинен повідомити про нестачу даних Оркестратора або Користувача і задати уточнюючі питання. 
- Краще задати питання і зупинити процес, ніж написати непрацюючий або неправильний код на основі припущень.

## 2. Approval Gate (Погодження масштабних змін)
- Жодні масштабні зміни коду (рефакторинг, зміна архітектури, зміна логіки БД) не виконуються без явного погодження Користувача.
- Оркестратор зобов'язаний збирати дані від суб-агентів, зводити їх у файл `implementation_plan.md` з увімкненим прапорцем запиту на погодження (`request_feedback = true`).
- Робота може продовжуватися лише після того, як Користувач натисне "Proceed" або дасть письмовий дозвіл.

## 3. Чіткий розподіл (Ієрархія та Оркестрація)
- Кожен суб-агент отримує лише ту зону відповідальності, яка потрібна для задачі (наприклад, тільки фронтенд, тільки парсинг, тільки логування).
- Суб-агенти не взаємодіють між собою безпосередньо. Вони звітують Головному Агенту (Оркестратору).
- Оркестратор несе відповідальність за зведення результатів та надання Користувачу зрозумілого фінального звіту.
